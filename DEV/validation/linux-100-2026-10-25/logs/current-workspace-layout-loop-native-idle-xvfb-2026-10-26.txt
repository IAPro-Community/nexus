Root cause (reproduced before the fix): ensureSurface() called deduplicateWorkspaceSurfaces(), whose tree walk allocated a new model/root even when there were no duplicate surfaces. WorkspaceCoordinator reruns its pinned-surface ensure effect whenever the Workspace context identity changes, so the new identity triggered another ensure/render. In an isolated WebKit inspector session on the previous source build, a 6-second sample recorded 1,024 document.title writes, 1,024 WorkspaceLayoutPersistence 500 ms timer installs and 1,024 DOM mutations. The installed pre-fix process separately measured 111.6% of one CPU core over 12 seconds in logs/current-native-webkit-idle-sample-2026-10-26.txt.

Fixes:
- deduplicateNode() now preserves unchanged stack/split identities, and deduplicateWorkspaceSurfaces() returns the original model when the tree is unchanged.
- Removed the always-spinning update-available icon from ProjectOverviewSurface as well as the top bar. Both alerts remain available and actionable.
- Added model identity/deduplication regressions and an overview update-alert static-animation regression.
