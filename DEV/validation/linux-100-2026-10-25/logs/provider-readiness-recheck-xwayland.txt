Finding and correction
The provider API had a 2-second detection deadline. A locally installed JavaScript CLI probe took about 2.2 seconds while the first-run readiness screen and system checks were running concurrently. The API then marked that provider absent, even though its imported profile was authenticated. The detection deadline is now 5 seconds. No credential data is logged or returned by this change.

Automated regression
`go test -count=1 -run '^TestHandleProvidersAllowsSlowLocalCLIProbeToComplete$' -v ./internal/control/web` — PASS. A fake Gemini detection sleeps 2.5 seconds, then returns Installed=true; the endpoint returns it as installed within the new 5-second deadline. Full package `go test -count=1 ./internal/control/web` — PASS (22.710s). Logs: `provider-detection-regression-test.log` and `provider-web-package-regression-final.log`.

Native procedure and outcome
The exact final Desktop binary above was launched as a real Wails application in XWayland with NEXUS_CONFIG_DIR, NEXUS_DATA_DIR and all XDG directories isolated under a disposable /tmp profile. The native “Importar sessões existentes” button copied four host sessions (Codex, Gemini, AGY and OpenCode); the UI reported 4 imported, 0 already authenticated, 1 without an importable session, 1 unsupported and 0 failures. Imported auth files were mode 0600. Claude had no importable session; Cursor remains unsupported. The same binary was stopped with SIGTERM and restarted using the same isolated profile. The UI then detected four providers with accounts. The original provider sessions were not modified.
