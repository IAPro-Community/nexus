### Cost parity decision (#241)

The SDK `cost.Summarize` accepts only an ID, optional micro-USD value and an `Estimated` bit. A local uncommitted SDK prototype `cost.ProjectEvidence` separates provider-reported, API-equivalent estimate, inferred, unclassified and unknown costs, and computes nullable token/performance totals. The returned aggregate does not retain the source rows or attribution; the host must retain and group its own ledger before projecting a scope. Tests cover each evidence class, missing versus zero measurements, duplicate IDs, invalid values and overflow. The prototype does not implement the Nexus durable ledger, SQL aggregates, budgets, anomaly baselines or product preferences. It has no immutable SDK revision, hosted CI, independent review or consumer pin, so Nexus does not call it. Revisit the adapter after SDK review and exact-SHA CI.

### Follow-up — runtime resolver provenance boundary

The current Nexus Windows resolver has special handling for npm `.cmd` provider shims to avoid passing provider arguments through `cmd.exe`. That safeguard was added in Nexus commit [`b69f4683`](https://github.com/IAPro-Community/nexus/commit/b69f4683496c24ecb7365e23a510d7dbbea0b1ad), whose historical tree carries the proprietary Beta License; it is not included in the SDK's MIT provenance inventory. It is therefore not copied into the SDK or deleted from Nexus. The pinned SDK resolver is not yet a behavior-equivalent replacement. #238 remains partial pending rights/provenance review and a separately reviewed shared implementation with equivalent Windows regression coverage.

### Follow-up — post-dispatch replay prohibition

The #239 audit found MissionRunner single and parallel paths that interpreted a typed quota/rate-limit result after provider dispatch as permission to allocate another account. Runtime identity and a failure classification do not establish that no partial output or external effect occurred. Both paths now preserve `DispatchFailed`, runtime and failure attribution, set `ReplayProhibited`, and stop for reconciliation; no subsequent account is selected. Unknown classified failures after dispatch are treated the same way. Only a proven pre-dispatch failure remains eligible for automatic recovery. Regression coverage verifies zero reallocations and a single provider call. Current evidence is recorded in `DEV/VERIFY.md`; this reduces autonomous recovery for post-dispatch quota failures until a provider supplies trustworthy no-output/no-effects evidence.
